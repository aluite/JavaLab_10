## 🛠️ Технические условия и методология
* **Среда исполнения:** Java SE Runtime Environment (JDK 17) / Онлайн-компилятор.
* **Кастомная аннотация:** Разработана аннотация `@Version` с двумя обязательными элементами: `number()` (строковый номер версии) и `author()` (строковое имя разработчика).
* **Жизненный цикл метаданных:** Аннотации задана политика `@Retention(RetentionPolicy.RUNTIME)`, что делает её доступной в памяти во время работы приложения. Целью (`@Target`) определен исключительно уровень методов (`ElementType.METHOD`).
* **Стабилизация вывода:** Для исключения хаотичного вывода методов (так как JVM не гарантирует порядок при вызове `getDeclaredMethods()`) в код внедрена принудительная алфавитная сортировка через `Arrays.sort` с компаратором по имени метода.

## 💻 Исходный код программы (Single File Структура)

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;
import java.lang.reflect.Method;
import java.util.Arrays;
import java.util.Comparator;

public class Main {

    // 1. Определение пользовательской аннотации для контроля версий
    @Retention(RetentionPolicy.RUNTIME)
    @Target(ElementType.METHOD)
    public @interface Version {
        String number();
        String author();
    }

    // 2. Тестируемый класс Software (Содержит аннотированные методы и один обычный)
    public static class Software {
        @Version(number = "1.0", author = "Alice")
        public void featureOne() {
            System.out.println("Feature One");
        }

        @Version(number = "1.1", author = "Bob")
        public void featureTwo() {
            System.out.println("Feature Two");
        }

        // Реализация требований СР: метод без аннотации версии
        public void unannotatedMethod() {
            System.out.println("This method has no version metadata");
        }
    }

    // 3. Крайний случай: Тестируемый класс полностью БЕЗ аннотаций
    public static class NoAnnotationsClass {
        public void anyMethod() {
            System.out.println("Just a method");
        }
    }

    // 4. Главный метод (Точка входа)
    public static void main(String[] args) {
        System.out.println("=== Проверка управления версиями (Software) ===");
        checkSoftwareVersions(Software.class);

        System.out.println("\n=== Проверка класса БЕЗ аннотаций (Крайний случай) ===");
        checkSoftwareVersions(NoAnnotationsClass.class);
    }

    // 5. Процессор рефлексии и обработки метаданных
    private static void checkSoftwareVersions(Class<?> clazz) {
        System.out.println("Анализ класса: " + clazz.getSimpleName());
        Method[] methods = clazz.getDeclaredMethods();
        
        // Сортировка по имени для стабильности результатов
        Arrays.sort(methods, Comparator.comparing(Method::getName));

        int unannotatedCount = 0;

        for (Method method : methods) {
            // Защита от NullPointerException с помощью безопасной проверки наличия маркера
            if (method.isAnnotationPresent(Version.class)) {
                Version version = method.getAnnotation(Version.class);
                System.out.println("Method: " + method.getName() 
                        + ", Version: " + version.number() 
                        + ", Author: " + version.author());
            } else {
                // Подсчет количества неаннотированных методов
                unannotatedCount++;
            }
        }
        System.out.println("Количество методов без аннотации @Version: " + unannotatedCount);
    }
}
```

## ❓ Ответы на вопросы для самопроверки

1. **Основные понятия темы «Аннотации и рефлексия» своими словами:**
   * *Аннотация* — это специальная пассивная метка (декоратор), добавляемая к элементам исходного кода. Она хранит служебную информацию, предназначенную для чтения внешними инструментами или средой выполнения.
   * *Рефлексия (Reflection)* — способность программы исследовать собственную структуру «на лету» во время исполнения: динамически считывать приватные метаданные, узнавать сигнатуры методов и управлять объектами.
   * *Retention (Удержание)* — свойство, задающее рамки жизни аннотации. Параметр `RUNTIME` необходим, чтобы метаданные попадали в оперативную память и были видны механизмам рефлексии при запуске.
   * *Target (Цель)* — директива, аппаратно запрещающая ставить аннотацию на непредназначенные для этого участки кода (например, ограничение `ElementType.METHOD` запретит повесить аннотацию на поле класса или сам класс).

2. **Входные и выходные данные программы:**
   * *Вход:* Скомпилированные описания структуры классов (`Class<?> clazz`), содержащие или не содержащие целевые маркеры `@Version`.
   * *Выход:* Информационные строки с детализацией версий/авторов в консоли, а также вычисленные численные счетчики неаннотированных элементов.

3. **Проверенные ошибки и крайние случаи:**
   * Была проверена ситуация отсутствия аннотации на одном из методов класса. Программа отреагировала переходом в ветку `else`, увеличив счетчик пропущенных элементов.
   * Был проверен крайний случай передачи «чистого» класса без аннотаций. Программа успешно завершила циклы без генерации исключений, выдав точное аналитическое количество пустых методов.
